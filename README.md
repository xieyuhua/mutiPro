# MultiPro 通用程序管理器

一个 Windows 托盘程序，用来同时管理多个长驻命令行程序：启动、停止、重启、日志、崩溃自动重启，以及可选的运行状态探测。

**不依赖 .NET / Java / Python 等任何运行时**，产物是单个原生 exe，复制到任意 Windows 机器即可运行。

不绑定具体程序。被管理的程序完全由界面里的配置定义：exe 路径 + 命令行参数模板 + 参数表，模板里用 `{key}` 引用参数表的值。因此同一个管理器可以同时管理 `vnt-cli.exe`、`frpc.exe`、`python server.py`、`node app.js` 等任意组合。

## 构建

需要 Go 1.21+：

```bat
build.bat
```

产物 `dist\MultiPro.exe`（约 6.7 MB，静态链接，无 cgo）。

构建细节：

- `-H=windowsgui`：以 GUI 程序启动，不弹控制台窗口。
- 嵌入 `gosrc/app.manifest`：声明 Common-Controls v6。**这一步不能省**，缺失时 walk 的 tooltip 初始化会失败，窗口创建不出来。
- 清单已生成为 `gosrc/rsrc_windows_amd64.syso`，随源码保存；`app.manifest` 改动后删掉该文件重新构建即可。

## 源码结构

| 文件 | 职责 |
|---|---|
| `gosrc/config.go` | 配置模型、占位符替换、exe 路径解析、探测输出解析、JSON 读写 |
| `gosrc/runner.go` | 单个程序的进程生命周期、日志、崩溃重启、优雅停止、UAC 提权启动 |
| `gosrc/system.go` | 开机自启、管理员权限检测、系统内置图标、配置目录 |
| `gosrc/editdialog.go` | 添加/编辑程序对话框 |
| `gosrc/main.go` | 主窗口、程序列表、详情、日志、托盘、定时刷新 |
| `gosrc/logic_test.go` | 解析/配置/路径相关单元测试 |
| `gosrc/runner_test.go` | 真实子进程的生命周期测试 |

## 快速开始

1. 双击 `dist\MultiPro.exe`。
2. 点左下「添加」，选择「程序路径」。
3. 填「命令行参数」，例如 `-k {token} -s {server}`。
4. 在「参数表」里每行写一项 `key=value`：
   ```
   token=abc123
   server=example.com:8004
   ```
5. 保存后点「启动」。

## 配置项

### 基本

| 配置项 | 说明 |
|---|---|
| 名称 | 列表和托盘中显示的标识，仅用于展示 |
| 程序路径 | exe 路径。可以用相对路径（相对 MultiPro.exe 所在目录），也可以只写命令名（自动去 PATH 查找） |
| 工作目录 | 留空则使用程序所在目录 |
| 命令行参数 | 完整参数模板，支持 `{key}` 占位符 |
| 参数表 | 每行 `key=value`；值里可以包含空格、中文、`&`、`=`、引号 |
| 停止命令 | 优雅停止参数，例如 `--stop`。留空则直接结束进程；超时后一律强制结束（含子进程） |
| 停止超时 | 执行停止命令后等待进程自行退出的时间 |

占位符替换后，仍会展开 `%ENV%` 形式的环境变量。未定义的 `{key}`（参数表里没有对应键）会原样保留，便于发现拼写错误。

### 运行方式（脚本执行）

被管理的目标不限于 `.exe`，也可以直接是脚本。默认按扩展名自动选择解释器：

| 扩展名 | 自动使用 |
|---|---|
| `.bat` / `.cmd` | `cmd.exe /c` |
| `.ps1` | `powershell.exe -ExecutionPolicy Bypass -File`（找不到时尝试 `pwsh.exe`） |
| `.py` | `python.exe`（找不到时尝试 `py.exe`、`python3.exe`） |
| `.js` | `node.exe` |
| `.vbs` | `wscript.exe` |
| `.sh` | `bash.exe` / `sh.exe` |
| `.exe` 或其他 | 直接运行 |

| 配置项 | 说明 |
|---|---|
| 执行方式 | `自动识别` 按扩展名判断；也可强制指定为直接运行或某个解释器 |
| 解释器路径 | 可选。留空时自动从 PATH 查找；也可填 Python/Node 的完整路径 |

脚本模式仍支持 `{key}` 参数占位符，命令会追加在脚本路径之后。列表的「类型」列会显示实际识别结果，图标则取自对应解释器。

### 定时执行

「启动时间」和「停止时间」各只有**一个输入框**，两种写法自动识别，不会冲突：

| 填写内容 | 触发方式 |
|---|---|
| `08:30` | 每天 08:30（`HH:MM`，小时可省前导零） |
| `0 8 * * 1-5` | cron：工作日 08:00（含空格即按 5 段 cron 解析） |

留空表示不启用。切换写法不需要改设置，直接把框里的内容换掉即可。

| 配置项 | 说明 |
|---|---|
| 启动时间 | 到点自动启动（已在运行则跳过） |
| 停止时间 | 到点自动停止 |
| 周期重启 | 每隔 N 分钟自动重启一次，适合有内存泄漏的长驻服务。`0` 表示关闭 |

**Cron 写法**：`分 时 日 月 周`，支持 `*`、数字、范围 `1-5`、列表 `1,4,7`、步长 `*/15`。

| 常用写法 | 含义 |
|---|---|
| `00:00` | 每天零点 |
| `23:00` | 每天 23:00 |
| `*/5 * * * *` | 每 5 分钟 |
| `0 * * * *` | 每小时整点 |
| `0 9 * * 1-5` | 工作日 09:00 |
| `0 8 * * 1` | 每周一 08:00 |
| `0 3 1 * *` | 每月 1 日 03:00 |
| `0 4 1 1,4,7,10 *` | 每季度首日 04:00 |

输入框旁的「示例…」内置 20 条常用规则，选中即可填入。填写时下方会实时显示中文含义，格式错误会直接指出原因。

> 标准 cron 规则：日和星期**同时**限定时满足任一即触发（如 `0 0 1 * 1` = 每月 1 日或每周一）。

同一分钟内只触发一次。触发动作会写入该程序的运行日志。列表的「定时」列显示当前生效的规则。

> 定时依赖 MultiPro 自身在运行。需要长期生效时请同时勾选「开机自启」。

> 旧版本把 `HH:MM` 和 cron 存在两个字段里，读取旧配置时会自动合并：cron 若有值则覆盖简单时间，然后清空旧字段。

### 行为

| 配置项 | 说明 |
|---|---|
| 以管理员身份运行 | 通过 UAC 提权启动。为了让提权程序也能看到日志，实际入口是一个提权的 `cmd.exe`：它负责把目标程序的 stdout/stderr 写入临时日志文件，cmd 的退出码即目标程序的退出码。MultiPro 轮询该文件转发日志。`cmd.exe` 不可用时退回直接 runas，此时只能跟踪进程、没有日志 |
| 崩溃后自动重启 | 进程非正常退出时，按「重启间隔」重新拉起。主动点「停止」不会触发重启 |
| 应用启动时自动运行 | MultiPro 启动后自动启动该程序 |
| 重启间隔 | 自动重启前的等待时间 |

### 状态探测（可选）

程序不内置任何具体程序的解析器，只按你配置的规则展示。不启用时只显示进程本身的状态。

| 配置项 | 说明 |
|---|---|
| 启用状态探测 | 每秒检查一次，按间隔对运行中的进程执行查询命令 |
| 查询命令 | 独立启动一个只读查询进程，例如 `--info`、`status --json`。不会干扰主进程 |
| 输出格式 | `Lines`（原样逐行）、`KeyValue`（`键: 值`）、`Json`（扁平化键值，嵌套用 `.`，数组用逗号） |
| 正常判断键/值 | 仅 `KeyValue`/`Json` 有效。例如键 `Connection status`、值 `Connected`，匹配时详情页显示为正常。值留空表示该键非空即正常 |
| 探测间隔 | 两次查询之间的最短时间 |

探测结果在详情页按平铺卡片展示，最多 40 项。查询失败或超时时保留上次结果。

示例：管理 vnt-cli

- 查询命令：`--info`，输出格式：`KeyValue`
- 正常判断键：`Connection status`，值：`Connected`

示例：管理输出 JSON 的程序

- 查询命令：`status --json`，输出格式：`Json`
- 正常判断键：`status.connected`，值：`true`

## 托盘与后台运行

- 点击窗口关闭按钮默认最小化到托盘，程序继续运行（可在底部取消勾选）。
- 左键单击托盘图标：显示主窗口。
- 右键菜单：显示主窗口 / 启动全部 / 停止全部 / 退出。
- 悬停图标显示当前运行数量。
- 只有托盘菜单的「退出」才会真正退出，退出时停止所有被管理的程序。

图标全部使用 Windows 内置资源，不需要任何 `.ico` 文件。

## 开机自启

勾选「开机自动启动本管理器」后写入：

```
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
```

开机后以 `--minimized` 启动，只留在托盘，并按各程序自己的「应用启动时自动运行」自动拉起。

## 管理员权限

需要管理员的程序有两种处理方式：

1. 对该程序勾选「以管理员身份运行」，每次启动时单独弹 UAC。
2. 直接以管理员身份运行 MultiPro，之后启动的程序都继承权限，不会再逐个弹 UAC。

底部实时显示当前是否具备管理员权限。

## 可靠性

这些行为是默认开启的，不需要配置：

| 机制 | 说明 |
|---|---|
| 单实例 | 重复启动会激活已有窗口后退出，避免两个实例各自拉起同一批程序造成端口冲突 |
| 配置原子写入 | 先写临时文件并刷盘，再替换正式文件；写一半崩溃不会留下损坏的配置 |
| 自动备份 | 每次保存前把上一版留为 `config.json.bak`；主文件损坏时自动从备份恢复 |
| 窗口位置记忆 | 记住大小与最大化状态，下次启动恢复；换显示器后若位置不可见会自动回退到居中 |
| 日志裁剪 | 内存与界面各保留约 20 万 / 12 万字符，超出后按**行**丢弃前半段，中文不会被截断成乱码 |

## 配置文件

```
%APPDATA%\MultiPro\config.json
```

JSON 格式，带缩进，可手工编辑。程序列表和全局选项都在里面；菜单「选项 → 打开配置目录」可直接打开。

同目录下还有：

- `config.json.bak`：上一版配置，手工改坏时可用于恢复
- `window.json`：窗口位置与大小，由程序自动维护

## 界面

- **菜单栏**：所有操作都在这里，不占用窗口高度。
  - 程序(&P)：添加（Ctrl+N）、编辑、删除、启动、停止、重启
  - 批量(&B)：启动全部、停止全部
  - 选项(&O)：开机自启、关闭时最小化到托盘、打开配置目录
  - 关于
- **程序列表**：右键直接操作当前行（添加 / 编辑 / 删除 / 启动 / 停止 / 重启），
  双击一行等于编辑。列包含 名称、状态、PID、类型、定时，首列显示图标。
  图标优先取程序自带的资源；若 exe 本身没有图标（Go、C# 编译的程序很常见），
  会按程序名首字生成一个彩色圆角图标，颜色由名称哈希决定，同名程序始终同色。
- **标题条**：程序名、连接状态、PID 与运行时长，只占一行。
- **选项卡**：默认显示「运行日志」，第二个是「运行状态」，两者都占满剩余高度。
  - 运行日志：按程序切换、清空、复制全部；左上角显示类型 / 定时 / 探测摘要。
  - 运行状态：启用探测时按配置解析出的键值卡片，标题会显示解析到的条目数。
- **状态栏**：一行文字，显示程序总数、运行数量、定时数量与当前管理员权限。

## 日志

- 每个程序独立缓存日志，切换选中程序时显示对应内容。
- 单个程序最多保留约 20 万字符，超出后丢弃前半段。
- 统一使用 CRLF 换行，Windows 编辑控件中按行显示，不会挤成一行。
- 以管理员身份运行的程序日志通过临时文件中转，约 0.4 秒刷新一次，会略有延迟。
- 程序启动后 5 秒内非零退出时，日志会追加一条诊断提示（常见原因是端口被占用）。
- 定时触发、自动重启等调度动作也会写入日志。

## 已知限制

- 仅 Windows。
- 探测只支持按配置解析输出，不内置任何程序专用解析器。需要新字段时调整探测配置即可。
- 停止命令是「启动一个新进程执行该参数」，不会向主进程 stdin 写内容。
- 自动重启不区分「崩溃」和「正常退出」，只要不是用户主动停止就会重启。
